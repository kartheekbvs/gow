# PyDocs Dojo — authoring guide

The Dojo is the practice-notebook side of PyDocs: six tracks, 36 notebooks,
141 exercises, every one graded by a real Python runtime. This file explains
how the content pipeline works so you can add or edit exercises safely.

```
practice.html              entry page (styles + script tags)
practice/dojo.js           the notebook editor app (views, editor, XP, routing)
practice/dojo_worker.js    Pyodide web worker that executes user code
practice/data/harness_py.js     the test harness (single source of truth)
practice/data/<track>.js        GENERATED track data — never hand-edit
practice/parts/<track>/         notebook fragments (the source of truth)
scripts/build_track.py     fragments -> data file
scripts/verify_practice.py the gate: schema + pedagogy + correctness
```

## The golden rule

**Edit fragments in `practice/parts/`, then rebuild.**
The files in `practice/data/` are generated by `scripts/build_track.py`;
hand-edits to them will be silently overwritten.

```bash
# rebuild one track and run the full verifier on the result
python3 scripts/build_track.py practice/parts/meta_py_core.json \
                          practice/parts/py-core \
                          practice/data/py_core_a.js --verify

# verify everything (run this before every commit)
python3 scripts/verify_practice.py
```

A track may ship in several data files (py-core is split into
`py_core_a.js` / `py_core_b.js`); the app merges them by `id`, so keep the
`meta_*.json` identical across the parts and give notebooks a global `order`.

## Track metadata (`meta_*.json`)

```json
{ "id": "numpy-reasoning", "title": "NumPy Reasoning", "icon": "🔢",
  "tagline": "…", "accent": "orange", "engine": "python",
  "packages": ["numpy"] }
```

`accent` is one of blue / orange / yellow / green / purple / red / cyan.
`packages` are Pyodide package names loaded before code runs (numpy, pandas).

## Notebook fragment (`practice/parts/<track>/<notebook>.json`)

```json
{ "id": "np-broadcast", "title": "Broadcasting", "icon": "📡",
  "level": "beginner|intermediate|advanced", "order": 20,
  "conceptRef": "numpy.html#s6", "blurb": "one-line pitch",
  "cells": [ <concept cell>, <exercise cell>, … ] }
```

`order` is a global sort key (steps of 10 leave room to insert). `conceptRef`
links back to the reference page section the notebook trains.

### Concept cell

```json
{ "type": "concept", "title": "…",
  "body": "<p>HTML: the mental model, why it matters, the gotchas…</p>",
  "demo": { "code": "print('runnable in the browser')" } }
```

Every notebook must open with concept cells before its first exercise (the
verifier enforces this). Demos run through the same harness as exercises.

### Exercise cell — code mode

```json
{ "type": "exercise", "exercise": {
  "id": "np-broadcast-1", "title": "Sensor Grid Alignment",
  "difficulty": "easy|medium|hard", "tags": ["broadcasting"],
  "mode": "code",
  "statement": "<p>HTML problem statement with a concrete story…</p>",
  "constraints": ["1 <= n <= 10^5"],
  "examples": [ { "call": "f(…)", "returns": "…", "why": "…" } ],
  "starter": "def f(...):\n    pass\n",
  "func": "f",
  "tests": [ { "label": "basic", "args": [ ... ], "expected": …,
               "hidden": false, "max_ops": 48000 } ],
  "hints": ["nudge", "bigger nudge", "the answer, as code"],
  "reasoning": "<p>why the solution works — the transferable idea</p>",
  "solution": "def f(...):\n    …" } }
```

XP matches the verifier: easy 10 / medium 20 / hard 35. Tests need at least
one visible example, and hidden tests must probe harder corners of the same
shape. `args` may embed harness markers:

| marker | meaning |
| --- | --- |
| `{"__np__": {"data": […], "dtype": "int64"}}` | numpy array |
| `{"__df__": {"columns": […], "rows": [[…]]}}` | pandas DataFrame |
| `{"__ser__": {"values": […], "name": "x"}}` | pandas Series |
| `{"__set__": ["a","b"]}` / `{"__tuple__": [1,2]}` | set / tuple |
| `{"__repeat__": {"item": […], "times": n}}` | item * n (use a **list** item to repeat a list) |
| `{"__opcount__": {"data": […]}}` | instrumented list that counts element inspections |
| `{"__nan__": true}` / `{"__inf__": 1}` | NaN / ±Infinity |
| `{"__perm__": {"n": 9, "skip": 4}}` | deterministic shuffled permutation |

Efficiency tests pair `__opcount__` args with `max_ops`: the harness charges
1 op per element read, `len(data)` per membership test and per sort; the run
fails if the budget is exceeded. This is how the Dojo teaches complexity
without wall-clock timing — but note the counter only sees the *original*
arguments, so converting to a plain `list()` first evades it. Write budgets
for the pedagogy, not as anti-cheat.

### Exercise cell — predict mode

```json
{ "type": "exercise", "exercise": {
  "id": "ml-sklearn-1", "title": "Predict: …", "difficulty": "easy",
  "mode": "predict", "tags": ["sklearn"],
  "statement": "<p>execute this in your head…</p>",
  "code": "the snippet to reason about",
  "options": ["A. …", "B. …", "C. …", "D. …"],
  "answer": 0,
  "explain": "<p>why the right option is right and each trap is wrong</p>" } }
```

Predict exercises pay the same XP by difficulty and need no tests.

## What the verifier checks (all must pass)

1. Harness self-tests (13 groups) inside CPython.
2. Data files are strict JSON in the `push(...)` wrapper.
3. Schema: required fields, enums, unique ids, `conceptRef` targets exist.
4. Pedagogy: concept cells precede exercises; hints and reasoning exist.
5. **Correctness: every reference solution passes every test, visible and
   hidden, executed by the same harness the browser uses.**
6. Non-vacuity: a pass-only stub must fail at least one visible test.

`ALL CHECKS PASSED ✓` is the bar for committing. The browser cannot lie to
you: `practice/data/harness_py.js` is the *only* harness, shared by Pyodide
(in `dojo_worker.js`) and CPython (in `verify_practice.py`).

## The editor, briefly

`practice.html` loads `shared.js` (site chrome), the harness, and every track
data file, then boots `practice/dojo.js` after layout injection. Views are
hash-routed: `#/` home, `#t=<trackId>` track, `#t=<trackId>&n=<nbId>`
notebook. Progress, drafts, revealed hints and XP live in `localStorage`
under `dojo.v1`. Code runs in a Web Worker owning one Pyodide runtime
(packages stay warm); first boot downloads ~10 MB from the jsDelivr CDN, so
the page is fully static and hostable anywhere — including GitHub Pages.
